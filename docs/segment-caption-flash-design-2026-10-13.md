# 片段简单字幕与闪白衔接设计

日期：2026-10-13。状态：Grok 补充讨论有条件通过；已实现本地 MVP，完整回归与真实渲染通过，等待用户验收，未部署生产。用户补充：时间段中间使用简单字幕。见[本地验收记录](verification/segment-effects-dev-2026-10-13.md)。

## 用户操作

保留已有“开头字幕 / 剧情片段 / 结尾画面”分区。在剧情片段每行的时间输入右侧增加“本段字幕（选填）”；窄屏放到该行下一行。第一个片段也可以填，满足片头时间提示；原有开头 Hook 的能力不变。

```text
剧情片段

片段 1  [集号] [开始时间] 至 [结束时间]  [本段字幕，选填           ]

                  与下一段衔接  [✓ 闪白]

片段 2  [集号] [开始时间] 至 [结束时间]  [one hour ago            ] [移除]
                                              显示 [1.5] 秒

                  与下一段衔接  [  闪白]

片段 3  [集号] [开始时间] 至 [结束时间]  [本段字幕，选填           ] [移除]

[＋ 添加片段]
```

- 字幕框空白即关闭，填写后显示“显示秒数”，默认 1.5 秒。每段只提供一条起始字幕；不提供任意时刻关键帧编辑。
- 字幕默认 72 px（1080 宽等比缩放），统一普通白字、黑描边、中上部水平居中；不加 AI、重点词、字体菜单、动画模板。使用应用内置支持中文的字体，按输出分辨率等比缩放。
- 字幕从本段开始显示，到配置时长或本段结束时消失。用户填写内容原样呈现，允许正常中英文标点；最多三行，排版放不下时明确报错，不能默默删字。
- 闪白位于两行中间，每个接缝单独开关，默认关闭。第一段前、最后一段后均不自动添加。
- 闪白默认总时长 0.5 秒，开启后可设置 0.2～5 秒；前后各分配约一半，按输出帧率取整，白峰对齐切点。短片段自动收窄效果窗口。保存字段为 `transition_duration_ms`，严格整数毫秒，默认 500，范围 200～5000。
- 这些都是画面叠加，不增加独立白色视频或字卡，不改变剪辑内容顺序和计划总时长，不混合相邻段对白。

上述时长和位置是建议默认值，不是用户已确认的逐项参数。

## 时间和图层规则

1. 段字幕使用本段相对时间，不输入原片时间或累计成片时间。第二段前面增加/删除片段时，字幕跟随本段。
2. 时间轴和效果窗口最终使用输出帧坐标。不能仅累加用户输入毫秒：当前 `_concat_units` 使用实际片段帧数决定视频拼接及音频裁剪边界。
3. 渲染底片时记录每段实际帧数与累计起止帧，作为字幕、闪白、预览、审计的共同依据；旧底片没有这些元数据时，为新增效果重新构建，不能从成片总时长或总帧数反推内部接缝。包复制和 fallback 都校验累计帧数等于底片总帧数，并用可辨认切点的合成素材验证每个内部边界；仅总数相等不够。
4. 段太短时收窄该接缝闪白两侧窗口，不能覆盖整段或与下一接缝的闪白重叠。建议每侧最多占对应片段帧数的半数并至少留一帧原画面；收窄后不足两帧的渐变侧拒绝启用并提示。白峰仍在切点，实际窗口在校对摘要中展示。
5. 有字幕且时长超过本段时，在界面提示实际显示时长，保存的仍是用户请求时长，后续加长片段可以恢复显示。字幕绝不延伸到下一段。第一版不做闪白结束后自动延迟字幕，也不做字幕淡出动画。
6. 图层从底到顶：剧情画面 → 闪白 → 简单段字幕 → 开头 Hook。静态片尾仍单独追加。源视频自带字幕属于剧情画面，会一起变白。
7. Hook 与段字幕时间重叠时用实际文字框检查位置冲突；发现冲突必须提示调整现有 Hook 位置或时长，不静默隐藏任何一项。无动态预览时不能声称已经核对遮挡。

## 拟新增的内部契约

以下是新功能的设计提案，不是现有 API 字段，也不涉及猜测第三方 API。

- 每个 episode 时间段可选 `segment_caption`，含 `text`、`duration_ms`。缺省或空文字表示无字幕；时长建议限制 100～10000 毫秒，仅接受整数毫秒，不接受负数、非数值或无穷值；样式由版本化的固定规则统一提供。
- 每个 episode 时间段可选 `transition_in`，只允许 `none` / `flash_white`。它表示“进入本段前的接缝”，界面画在该段上方。这样无需用另一份按下标排列的转场数组。
- 第一段的入场转场必须为 none；片段删除导致原第二段变第一段时，前端清除其入场效果并提示。后端拒绝矛盾输入，不能默默改写。
- 删除中间片段时，后段自己的入场闪白跟随该段，应用到新的前段接缝，刷新摘要告知变化；复制片段带上字幕和入场设置。新增片段默认无效果。
- 同一段原片重复使用时，效果分别归属各个片段对象，不能按集号/原片起止时间去重。
- 结构化 clips 或 composition 是本行唯一编辑源，直接生成带效果的 TimelineItem；`timeline_text` 只作为兼容展示投影。出现两个结构化来源时明确校验，不继续顺序覆盖。
- 纯文本旧草稿仍按旧语法解析。只有可以无损投影为片段表单的时间线才开放新控件；含字卡、未解析终点等暂不支持的情况明确提示，保留原始内容。后端拒绝字卡或开放终点项携带新效果；已有只读内容可展示效果摘要，但不能被转换后静默清空。含新效果的草稿不可通过文本编辑静默降级。
- 文本识别“追加”保留已有段设置；“替换”清晰告知会替换段及附属效果；撤销恢复完整段对象。已有字卡语法保持原含义，不借字卡承载叠加字幕。
- 数据 schema_version 保持 1，新增字段可选，老数据读取得到无效果。旧程序会忽略未知字段，因此兼容性不能只看是否能解析；发布前必须在发布/回退入口建立功能版本兼容闸，旧入口不得编辑或重制含效果任务。不能指望旧进程理解新加的模型校验；在无法保证隔离时拒绝回退到不支持版本。兼容闸与回退验收完成前不能上线。

## 渲染方案取舍

优先保证时间与图层一致，第一版不扩展现有 Hook 的 GOP 局部拼接为通用任意窗口拼接。

推荐路径：纯剪辑底片 → 一次组合画面效果（闪白、简单字幕、Hook）→ 原静态片尾流程。简单字幕用现有 Pillow/内置字体机制生成透明图片，不将用户文本拼接进 FFmpeg 表达式；文字不触发 AI 调用。

- 没有新增效果时，继续已有 `_apply_hook` 和短 Hook 加速路径。
- 有新增效果时，从同一底片统一叠加，最多增加一次覆盖全片的视频编码；不能先加字幕、再闪白、再 Hook，造成多次全片编码或白色盖住文字。
- 纯底片身份从旧剪辑字段白名单构建，保持旧字段及其缺省/null 的序列化方式，不加入新的空效果字段；保留字卡 text/duration_ms、素材指纹和编码设置。效果身份包含底片内容身份、实际帧边界、规范化字幕/闪白参数、字体文件指纹和效果版本。最终成片身份仍包含完整 request。
- 只有确认实际帧边界、曲线、预览与成片一致之后，再评估按整段缓存效果或局部编码优化。不要同时承诺“修改字幕完全复用底片”和“所有效果都在原片首轮切段中烘焙”。
- 音频沿用底片切点，效果阶段优先复制底片音轨；不加转场音效、静音段或交叉淡化。容器不兼容时沿用已验证的音频规范化路径，验证无累积漂移。
- 原有 Hook 静帧预览继续明确标为 Hook 排版。动态衔接验收用最终成片预览；可后续增加接缝短预览，但必须使用同一效果计划和渲染器。

性能代价：带新增效果的长片可能比当前仅有短 Hook 的局部编码路径更慢。这是设计取舍，尚未实测，不能承诺不增加制作时间。

## 实现范围与验收

预计修改 `models.py`、`intake.py`、`web/app.js`、`web/index.html`、`renderer.py`、Hook 组合/预览相关函数、`timing_review.py`；新增独立效果计划与简单文字排版模块。沿用集中配置读取，不引入临时环境变量配置。保存与版本两条路径均补覆盖。

实施次序：先补清洗与保存回归 → 定义严格可选契约和直编译 → 两种表单控件与撤销 → 实际帧边界与组合效果 → 预览身份、缓存和版本 → 合成素材与参考风格验收。

验收至少包括：

- 片段表单和 composition 保存/刷新/复制均不丢设置；旧草稿默认无效果；非法值不悄悄回退。
- 首段/第二段字幕位置时间正确；重复原片片段独立；删除第一段和中间段的转场规则明确；识别追加/替换/撤销完整。
- 中文、英文、引号、百分号、冒号与换行；空白文字；超长两行；不出现缺字框或命令注入。
- 30 fps 及项目支持的其他帧率，非整帧毫秒、短段、多接缝；开启前后帧数和计划时长不变，音画无累积漂移。
- 闪白峰值、两侧渐变、顶部 Hook 可见、段字幕不被白层盖住；Hook 碰撞提示；静态片尾无闪白泄漏。
- 改文字只使效果/成片/有关预览失效；改原片范围、原片内容、渲染参数正确使底片失效；旧缓存缺少实际帧边界不能误用。
- 实际 FFmpeg 合成和浏览器验收，比较无效果基线与新增效果耗时。实现时用 `/Users/matao/miniconda3/envs/py3.12/bin/python3.12` 运行相关测试；发布前按项目要求跑完整套件。

## Grok 讨论

已取得首轮完整意见与补充复议。请求 `grok-4.7`，实际返回 `grok-4.7-build`；会话 `01a13471-f1aa-7e01-8459-993175ffc9e2`。初审与复议均进程退出 0、`stopReason=end_turn`，并返回完整非空审查。初审 high，补充讨论 medium；使用隔离 cwd、提供必要源码摘录，实际审查工具列表为空。

采纳：字段归属片段、入场闪白附着后段、草稿清洗显式保留、时间采用实际帧边界、底片身份使用旧字段白名单、Hook 避让取帧仍看纯素材、请求时长与实际显示时长分开保存/展示。

本版不采纳：字幕固定淡出（用户要求简单字幕，减少额外行为）；开放终点和字卡处主动开放新效果编辑（本版聚焦明确范围剧情片段）；局部 unit 效果编码作为首版默认。

局部编码复议依据：Grok 首轮没有 `_concat_units` 全文，提出先局部编码再拼接。本地核对当前拼接首选 H.264 视频包复制、音频按实际视频帧长重建，不兼容时整片编码；但是原始 unit 仅存在临时目录，base 命中后不会重新生成。要做到其所说“修改一行只重做相关 unit”，必须另外实现持久单段缓存，不能视为现有能力。

补充讨论结论：Grok 对本稿的一次组合叠加 MVP **有条件通过**，认为比新增 unit 缓存更适合当前架构。条件为实施后验证无效果快路径、精确帧边界、音画同步、图层、保存往返及旧版本入口闸；不是代码或效果已经通过验收。其“白峰在后段第一帧”的建议纳入实现验收，禁止用容器毫秒数作为接缝依据。
