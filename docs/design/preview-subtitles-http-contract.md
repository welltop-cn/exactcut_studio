# Preview subtitle HTTP contract (application-defined)

All routes require login and project access. The independent `preview_subtitles` configuration defaults off. No cutting edit permission is required; delivered current videos are readable.

`POST /api/batches/{batch_id}/preview-subtitles/{request_id}` accepts JSON with `source_sha256` (64 lowercase hex) and `version_id` (managed current version ID, or null for legacy). Existing UI's `revision` and `submission_token` metadata are ignored: this is an independent read-only auxiliary job, not a media mutation. Requires `X-Exactcut-Request: 1`. It enqueues idle/failed work or returns existing queued/running/completed work. No success-force-regenerate operation. Responds 202 for queued/running, 200 for completed, and 429 when the bounded queue is full or resources cannot be acquired. A durable FIFO starts up to `max_active_tasks` materials concurrently (default 2, configurable 1–2), with `max_queued_tasks` defaulting to 20 waiting tasks (excluding active tasks). Each material's segments remain sequential. Duplicate submissions reuse the same pending or active task, including the second worker.

`GET` on the same path requires query `source_sha256` and `version_id` (empty string for legacy). It only reads/recover-checks the matching current source; it never starts a model call.

Success envelope: `{enabled:true,binding:{batch_id,request_id,source_sha256,version_id},report:{id,status,progress,cues,...}}`. `status` is idle/queued/running/completed/failed. Queued reports include queue_position (1-based while pending, 0 while being admitted); closing the preview or subtitle switch does not cancel the task. Pending tasks survive service restart, and execution rechecks the initiating account, project access, current source and recognition configuration. Idle has no durable task; running has real stage progress, started_at, completed_chunks, total_chunks. Completed has all validated cues, elapsed_seconds, completed_at, model. Empty cues is an explicit completed result, not failure. Failed has a safe error and no partial cues; retry requires an explicit POST. Reports may include created_at and schema_version=1. IDs are hashes of binding, model, prompt/schema and recognition settings.

Cues are application-defined `{start_ms,end_ms,original_text,translation_zh}`, in complete-video milliseconds, start inclusive and end exclusive. Only visible dialogue subtitles are recognized. Result text is untrusted and displayed as text.

Invalid inputs return 400; stale SHA/version returns 409; absent/deleted/inaccessible source returns 404; disabled feature returns 404; unavailable credentials/maintenance returns 503. Long model requests never hold the HTTP mutation lock. Existing task identity is protected by cross-process state/worker leases; an abandoned running task becomes failed and is never automatically recharged.

Caches live under the owning batch's `preview-subtitles/`; no video, media-state, render record, download or delivery file is modified. A changed binding cannot read old results even when request_id is reused.

Recognition prefers the current lightweight preview when its SHA-256 and master binding are verified; videos without a separate preview use the master. The result remains bound to the master SHA/version. Reports record `recognition_source` (`preview` or `master`), `recognition_bytes` and `recognition_sha256`. The recognition proxy never upscales, uses the configured sampling frame rate, removes audio and stays within the complete inline-request budget (including base64). Oversized segments split into two contiguous halves before a provider request; no minimum segment under 1 second is created by that split. Invalid/empty JSON, text or time results cause at most one additional request for that segment; provider/network errors are not blindly retried. Persistent validated segment checkpoints are isolated by exact recognition-video SHA, duration, model/prompt/schema and recognition policy, and revalidated when read. Explicit retries reuse successful segments. Failed segments never appear as a complete timeline. The optional version-1 queue `active_extra` list adds a second durable slot; the original `active` descriptor remains compatible. One dispatcher owns all worker slots and retains its lease until all workers exit. Recovery records stranded tasks as failed without automatically repeating requests.

All Chinese subtitles are browser preview tracks only. Export, download, rendering, replacing the master and publishing never consume these cues or checkpoints.
