# 飞书自动化负责 FBBM 交付

2026-10-15，依据用户确认的实际职责调整。尚未发布正式服务。

## 唯一执行方

ExactCut 只负责确认当前成片版本和 SHA-256、上传/复用 OSS 对象、按 OSS_URL 创建或复用飞书记录。首次创建仅写剧ID、OSS_URL、状态=待处理、来源四个字段，不写重试次数/剧集ID/序号/业务日期/OSS_KEY；复用不重置状态、不改写已有记录。

外部自动化负责 FBBM 登录、Meta 额度检查、创建素材、Facebook 同步/重试，以及飞书的 ADS素材ID、视频ID、状态等结果字段。

ExactCut 后续只 GET 飞书原记录，不登录 FBBM、不创建/重新同步素材、不更新飞书处理状态。保留本地只读观察结果供页面、交付禁剪、版本绑定和审计使用；这不是自行生成平台回执。

## 观察结果

- 「已完成」且 ADS素材ID、视频ID 都非空：本地标记 fbbm_ready。
- 「失败」「超时」：本地报自动化处理失败，并保留原记录和错误原因。
- 待处理、处理中、同步中、暂停、未知状态或完成字段未写齐：继续等待，绝不根据单一 ID 判成功。
- 记录 ID、OSS_URL 或已保存的 ADS素材ID 不一致：待核实，不自动接受另一个 ID。
- 尚无素材 ID 时的临时读取失败可以重试同一记录；原等待期限不变。
- 查询超时后用户可以继续查询原记录，应用不重置自动化状态或触发其重新创建。

只读 poll 在请求前原子保存可重试的本地意图，不写未知外部写入 pending 标记；进程中断由现有调度恢复原查询，保留原期限。旧版本留下的 pending/未核实回执不自动解锁，因为旧版可能实际发出过写请求。

历史冲突仍需单条对账；本次改动不批量修复或删除历史平台素材。不更改数据 schema 版本，不修改剪切、当前成片选择和已交付禁剪规则。

## 验证重点

测试中使 FBBM 客户端构造及飞书 update 直接失败，确保正常等待、完成、失败、核实和重试都不会调用它们。保留身份冲突、重复提交、父子交付状态和制作/剪切回归。

用户要求 Grok 审查后部署线上测试实例，并授权测试实例使用真实 OSS/飞书服务配置。因此测试实例上的用户上传会产生真实飞书待处理记录和真实 FBBM 素材；不把模拟测试声称为真实端到端验收。测试代码回滚到旧版本前必须先关闭交付，避免旧版重新参与 FBBM 创建。

## 真实表字段核对

通过 lark-cli 只读解析用户 Wiki 链接并读取「素材同步」表结构，实际共17字段。剧ID/来源为文本，OSS_URL为链接，状态为单选且有「待处理」。ADS素材ID/视频ID为文本，封面URL为链接，错误信息为文本；状态还包含处理中、同步中、已完成、失败、超时、暂停，均与观察分支一致。重试次数存在但本应用不写；剧集ID/序号/业务日期/OSS_KEY不存在。正式服务配置的 Base/table 与该链接解析出的标识一致（服务器只输出布尔比对结果）。未创建、更新字段或记录。
