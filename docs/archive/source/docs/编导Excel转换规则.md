# 编导 Excel 转换规则

> 历史归档（2026-11-04）。正文保留当时的方案或执行状态，不代表当前版本；日常操作见[文档入口](../../../README.md)。

版本：v1，更新于2026-09-24。适用于本批编导表及沿用相同约定的后续输入。时间与拼接规则已整理，制作设置另列待定项。

## 新表采用标准输入

最新显示约定：标准格式为`00:00:00`，三组均保留两位。用户要求说明文档只解读标准模板，不扩展三位数示例、毫秒数值范围或非标准转换章节。尚未确定的非零末组换算不作推断；不得通过截断、舍入或错误换算凑成两位。此条替代此前“仅零毫秒写00、其他保留三位”的说明。

最新分列方案见[标准剪辑Excel_分秒毫秒填写说明](标准剪辑Excel_分秒毫秒填写说明.md)：每片段填写集、头的分秒毫秒、尾的分秒毫秒，头尾全空表示全集，单端全空分别表示片头或片尾。该方案当前为下一版规范说明，下面的v2模板与代码仍是单格文本格式，尚未切换。

新版表头只填写剧ID、出表人；日期按制作当天（北京时间）自动确定，无需填写剧名、素材类型或Creator 2。已确认批次重跑沿用锁定日期。v2模板导入时严格检查四种片段格式，禁止中间跳格、点号简写、多段同格及省略字卡时长，错误定位到单元格。旧表沿用兼容导入规则。

新需求使用 `templates/标准剪辑需求_模板_v2.xlsx`。本文件的分.秒、裸集数、单起点、加号及逗号规则用于旧表兼容解读，不作为新表推荐填法。

新表统一四种写法：`EP1 00:05-01:49`、`EP2 全集`、`EP5 01:22-片尾`、`字卡|One hour earlier|1.5s`。一个片段一格，多段拆格，视频时间使用 `MM:SS` 或 `MM:SS.mmm`。因此第5秒写 `00:05`，半秒写 `00:00.500`，1分49秒写 `01:49`。字卡里的 `1.5s` 是1.5秒时长，与旧表视频定位的分.秒简写不同。

## 已确定的整理原则

1. 按剧 ID 分组，保存到 `projects/<剧ID>/requests/`。不覆盖原始 Excel，保存原文件副本。
2. 不遗漏原表记录。原始行号、创意原文、Hook 和业务日期均保留，缺失信息留空并说明。
3. 从左到右保留片段顺序，包括重复和回溯。同一集中的 `+` 拆为多个连续执行的片段。
4. 表格里的制作说明属于待整理数据。整理操作不自动授权制作、上传或投放。
5. 未知剧名、出表人、授权不从其他剧或引用文件名推断。未提供的 Hook 保持空白。
6. 不把待补时间线标记为可执行。编译、物料范围、时长及制作前检查须另行完成。

## 已确认的时间范围规则

以下规则由用户于2026-09-24确认，后续同类编导表复用：

- 只写集数（如 `EP4`）表示整集，从0秒到该集实际片尾。
- 集数后只写一个时间点（如 `EP5：1.22s`）表示从该时间点到片尾；本例起点为1分22秒，即82秒。
- 整集与开放结尾在视频到位后读取实际时长，生成明确起止时间。没有对应视频时标注“待读取片尾时长”，不再作为编导漏填起止时间处理。
- 用户随后确认 `1..44s` 多写了一个点，修正为 `1.44s`，按本表分秒格式整理为 `01:44`，保留原文和修正记录。
- 用户已明确确认 `0.5s` 等于第5秒，规范化为 `00:05`。本表点号按分秒分隔解释，点后是秒数：`1.49s` → `01:49`，`1.06s` → `01:06`。不把此规则应用于项目标准输入中的真正小数秒。

## 具体解析规则展示

| 输入 | 含义 | 规范输出示例 |
| --- | --- | --- |
| `5s` | 第5秒 | `00:05` |
| `0.5s` | 0分5秒 | `00:05` |
| `1.06s` | 1分6秒 | `01:06` |
| `1.49s` | 1分49秒 | `01:49` |
| `2.27s` | 2分27秒 | `02:27` |
| `1..44s` | 已确认的多点号笔误 | `01:44`，记录修正 |
| `EP7：0-29` | 未写单位的整数按秒解释 | `EP7 00:00-00:29` |
| `EP4` | 第4集全集 | `EP4 00:00-实际片尾` |
| `EP5：1.22s` | 从1分22秒到第5集片尾 | `EP5 01:22-实际片尾` |
| `EP1：0.5s-1.49s` | 第1集的指定区间 | `EP1 00:05-01:49` |
| `EP3：2s-35s+53s-1.45s` | 第3集两个区间依次拼接 | `EP3 00:02-00:35` → `EP3 00:53-01:45` |

“实际片尾”是规则展示占位符，不是可提交给编译器的时间码。转换工具必须读取视频实际时长后填入具体值。

### 拼接与字段

- 一行对应一条成片需求。以当前行剧ID定位正片，不借用其他剧的集数或时长。
- 去掉开头的栏目提示“正文画面——”；清理第45行开头多余的顿号等分隔符，不改变内容。
- 逗号分隔拼接步骤，从左到右执行；加号拆成同集的多个独立片段。
- 重复选段、先高集再低集、局部后接同集全集均原样保留。不要按集数排序或去重。
- 标题短文案保留为Hook，空白仍为空白；剧ID、业务日期和原始行号保留。
- 整理为 `片段1`、`片段2` 等独立列，另保留创意原文及转换说明。
- 每剧放入 `projects/<剧ID>/requests/`，原始文件另行归档。

### 完整示例

原文：`正文画面——EP1：0.5s-1.49s，，EP2`

1. 片段1：`EP1 00:05-01:49`，选段时长104秒。
2. 片段2：EP2全集，`EP2 00:00-实际片尾`。

原文：`正文画面——EP6：0s-9s，，EP1：32s-1..44s，，EP2`

1. 片段1：`EP6 00:00-00:09`。
2. 片段2：`EP1 00:32-01:44`，记录双点号修正。
3. 片段3：EP2全集，`EP2 00:00-实际片尾`。

### 校验与缺失处理

- 整集或开放结尾没有对应视频：标注“待读取片尾时长”，不标为编导漏填。
- 起点不小于终点、时间超出视频实际长度、分秒格式中的秒位达到60及以上：标注具体问题，不静默交换起止、截断或进位。
- 新出现的未知写法单独讨论，确认后再追加规则；已确认的规则无需重复询问。
- 元数据缺失、文件未定位和制作方式未定分别记录，不混成“时间码错误”。

## 规则确认后的复用方式

每项规则记录确认日期、适用输入写法、输出格式和无法处理时的回退方式，再更新本文件与转换工具。涉及整集和片尾的规则必须使用对应视频的实际时长，不使用虚构片尾或其他剧的时长。尚未确认的语义继续保留原文并标注待补。

当前通用编译器把小数秒按真正的小数秒解析，例如 `1.06s` 是1.06秒。因此，编导表的分.秒简写应在独立导入转换中显式改成 `1m6s`，避免改变现有标准输入的含义。

## 三列分组标准表导入

支持“工作簿1_标准格式.xlsx”的双行素材结构：第一行保留素材编号、Hook 和各组“集／头／尾”，下一行填写片段数据。两行合并为一条素材，按组从左到右拼接；转换记录工作表不作为制作内容。

时间输入为“分:秒:毫秒”，例如 `01:52:00` 是 1 分 52 秒，`00:01:125` 是 1 秒 125 毫秒。头空从 0 开始，尾空到片尾，头尾都空取全集。业务日期自动取制作当天。非法时间、缺失集号、中间空组或缺失数据行会定位到原表单元格报错，阻止错误导入。
