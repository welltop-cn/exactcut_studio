# 按时间线预下载正片

> 历史归档（2026-11-04）。正文保留当时的方案或执行状态，不代表当前版本；日常操作见[文档入口](../README.md)。

草稿剧 ID 有效（101050～999999）且包含至少一个有效剪辑片段时，工作台自动准备时间线涉及的集数，不需要先保存、补齐作者日期或确认制作。相同集数去重；增加新集只补下载缺失部分；已有完整缓存直接复用。下载、原片时长核对与进度刷新在后台进行，编辑中的未保存内容不会被服务器草稿覆盖。

编辑区显示逐集排队、下载百分比、就绪或失败；原片可用后自动核对片段边界。失败不会无限自动重试，使用“重试正片下载”。移除集数、切换或清空剧 ID 后，尚未开始的旧集数会跳过；已经开始的下载允许完成并作为缓存保留。

预下载沿用生产下载开关、账号项目权限、CSRF、现有串行任务队列和正片缓存锁。只下载整集原片，不自动制作、保存草稿或发布；正常预览与发布确认保持原流程。归档、暂停及非草稿项目不能启动预下载。

确认制作时若预下载尚未完成，制作任务会在现有串行队列等待。下载进度卡片继续读取该项目、本实例、同剧且属于已确认时间线的预下载进度，显示当前集号、已接收大小、百分比和已完成集数。进度只合并到网页响应，持久任务仍为queued；正式下载开始后使用正式任务进度，避免旧预下载覆盖新状态。

部署与迁移无需增加配置文件、环境变量或数据 schema。持久文件位于部署根 `data/.web-state/`：`jobs/<任务ID>.json` 保存队列，`batches/<项目ID>/source-prefetch.json` 保存最新引用集数，`source-prefetch-results/<任务ID>.json`（位于该项目目录内）保存逐集结果；任务日志沿用 `jobs/<任务ID>.log`。恢复与缓存清理沿用已有机制，未保存草稿所引用的预下载集数也会被保护，归档后释放保护。

验证使用独立临时数据、合成视频与模拟传输，无生产凭据或发布。覆盖首段触发、逐集增量、去重、取消后重新加入、权限、失败重试、进程重启恢复、实际子进程下载、时长核对及未保存编辑/过期响应保护。
