# 素材版本管理：真实服务器验收计划

> 历史归档（2026-11-04）。正文保留当时的方案或执行状态，不代表当前版本；日常操作见[文档入口](../../README.md)。

状态：保留的验收计划，不代表每一格均已实测。2026-10-11 已完成受限灰度发布；实际通过、未执行与测试环境边界见 [发布验收记录](material-lifecycle-release-2026-10-11.md)。真实 FBBM 未验收，新版交付及全量纳管关闭。

## 环境与边界

1. 本地：独立 fixtures 和全量回归，无生产凭据/数据。
2. 真实服务器隔离实例：独立目录、端口、数据根、环境标识及测试存储凭据，不连接生产交付服务。实际 Linux 文件锁、进程重启、调度及故障注入在这里验证。不得通过 staging 加载生产配置来图省事。
3. 线上灰度：专用测试账户/项目与独立合成视频，实际生产 OSS 私有前缀内由该项目生成对象；不删除测试对象，单列留下的对象清单。验证真实代理、鉴权、浏览器、签名和下载链路。不得重启全站或断网制造失败。
4. 真实 FBBM 创建/上传仅使用明确的测试目标；无可用测试目标时记录“未执行”，不能把 mock 结果写成线上通过，也不能用业务对象试验。正式发布前决定对应能力保持关闭，不能隐藏缺口。
5. 所有发布经现有 release manager；先检查无活动任务并正常排空。新权威状态启用后只允许支持该状态的兼容版本回退，禁止旧程序写入新版项目。

## 验收矩阵

| 场景 | 真实服务器隔离实例 | 线上灰度 | 通过标准 |
|---|---|---|---|
| 新建多素材项目、重复提交新增 | 必测 | 必测 | ID 唯一稳定，重复请求仅创建一次 |
| 修改后重新制作、复制新项目 | 必测 | 必测 | 前者保持项目/素材身份；后者全新身份 |
| 重排、改展示信息、删中间素材、再新增 | 必测 | 必测 | 其他素材 ID/文件/交付引用不变 |
| 双浏览器保存同一 revision | 必测 | 必测 | 一个成功，一个冲突，无静默覆盖 |
| 新编辑后的旧候选迟到、重复执行、执行权失效 | 必测，控制进程时序 | 非破坏性重复提交 | 旧候选无法成为 current |
| 渲染失败、预览失败、主片或预览上传失败 | 必测，注入每个失败点 | 检查失败项目展示 | 旧当前版本仍能播放和下载；候选可重试 |
| 成功上传两份媒体并发布 | 必测 | 必测 | 一次原子切换，master/preview 对应相同版本 |
| 调度持久化后、启动前崩溃 | 必测 | 不故障注入 | 重启恢复，无漏任务或重复副作用 |
| 文件落定、两次上传之间、current 提交前后崩溃 | 必测 | 不故障注入 | 不丢旧成片、不混用新旧；孤立对象保留 |
| 投影落后/损坏，权威记录缺失/损坏 | 必测 | 不改业务数据 | 投影可重建，权威异常阻止写入，无旧数据回退 |
| 删除/恢复与制作、补传、签名、审批并发 | 必测 | 测试项目必测 | tombstone 阻止迟到写回；恢复不复活旧任务 |
| 旧删除接口和 CLI 写入口 | 必测 | 验证权限/拒绝响应 | 不能绕过纳管保护执行物理删除或旧格式写入 |
| 历史数据正常/缺文件/hash 不符/未知交付 | 独立历史 fixtures 必测 | 只读盘点及合格测试项目 | 纳管幂等，异常隔离，原文件保留 |
| 预览过期续签、暂停 seek、切项目取消、快速连切 | 必测 | Chrome 必测 | 正确视频/时间点/暂停状态，旧响应不污染新项目 |
| 预加载期间刷新、接口并发、正式成片下载 | 性能基线 | Chrome 必测 | 请求到 OSS，HTML/API 无原先数十秒阻塞；下载字节 hash 正确 |
| 跨账户访问、删除素材签名、路径越界 | 必测 | 测试账户必测 | 越权拒绝；无签名泄漏；删除后不签发新 URL |
| 同内容 OSS 重用、不同内容不可覆盖 | 测试桶必测 | 测试项目必测 | 上传次数与引用一致，旧 key 内容不变 |
| OSS 复制交付与命名冲突 | 测试桶必测 | 明确测试目标才执行 | ETag/hash 校验；已有其他字节拒绝覆盖 |
| 旧版审批后 current 更新、已入队旧版、新版再次交付 | 独立交付 stub 必测 | 明确测试目标才执行 | 旧审批不能冒充新版，入队版本固定、历史交付保留 |
| FBBM 接收后响应丢失、重复确认、unknown 恢复 | 独立交付 stub 必测 | 不对业务目标注入 | 结果不明禁止自动重复，记录可核对 |
| 升级、兼容回退、任务排空 | 必测 | release manager 健康验收 | 不混用新旧写者，不恢复旧数据库覆盖新状态 |

## 性能与证据

灰度至少记录无视频与 OSS 预加载两组：每组 10 次项目切换、5 次刷新；保留 HTML 和详情 API 的 TTFB、总耗时以及视频请求 origin，列出中位数/最大值。暂定同网络条件下主文档/详情 TTFB p95 不高于 2 秒，且预加载组不高于基线两倍；未达标继续定位，不能把 OSS 请求成功当作页面性能通过。

每项记录：时间、环境、release/commit、用例 ID、输入 fixture、实际观察、通过/失败/未执行、证据路径。记录不包含密钥、Cookie、签名 URL 查询参数或业务视频。记录全部实际产生的测试 OSS key，维持禁删约束。

上线门槛：Grok 设计意见闭环、实现审查、全部本地/Linux 回归、真实服务器关键一致性故障用例通过、灰度浏览器性能与下载通过、可执行兼容回退完成演练。任何缺口必须明确列出，不能对未测试场景作“已覆盖”的承诺。

## Grok R2 增补

- 双恢复注入：父交付 outbox claimed，内部 intent unknown，删除的仅为隔离测试 fixture 中的作业记录；运行父恢复与内部恢复，断言没有新外部副作用，父 pending/unknown 不解除。线上不得删除业务作业记录做此实验。
- 命名别名：父项目与隐藏内部候选拥有相同预留名时，保存父草稿不改序号；第三项目申请同名仍被拒绝或按既有规则取得不同序号。
- 只读 OSS 审计实际结果（2026-10-11）：生产 SDK get_bucket_lifecycle 返回 NoSuchLifecycle，桶当前无配置生命周期；未修改桶规则。无法据此证明其他独立应用没有自建清理任务，保留此限制。
