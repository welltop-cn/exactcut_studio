## 实测场景

- 浏览器复制原配置，正常保存并制作，无缺失帧索引错误；重新分配素材 ID 和序号。短片草稿再次复制后，帧值、字幕、闪白和 Hook 参数保留。
- 粘贴识别：`第4集 00:02:003 至 00:14:002`、`第5集 00:03:006 至 00:15:005`，识别后的集号、顺序、帧序号一致。
- 手工将第一段改为 `00:02:004 → 00:14:003`，保存、刷新保持；第二段 `00:03:006 → 00:15:005`。确认制作后分别转换为 `[2133,14133)`、`[3200,15200)` 毫秒，每段 12000 毫秒 / 360 帧，合计 720 帧。结束帧按包含语义处理。
- 第二段字幕 `Twelve seconds later`，1500 毫秒；进入第二段闪白，500 毫秒。保存、刷新、复制均保留。实际成片抽查 12 秒切换处闪白，12.5、13.46 秒可见段字幕，13.5 秒已消失。
- 短片 Hook 为 `A SECOND CHANCE`，清晰简洁、上方、不强调、20 秒；字幕预览正常。成片 19.8 秒可见淡出，20.1 秒已无 Hook。长片保留手动强调和 AI 语义强调，实际预览正常；第二条含结尾图片和引导文案，播放至结尾正常显示。
- 短片基础剪辑与最终成片的音频包（PTS、DTS、duration、SHA256）完全一致，均 1035 包；视频和音频时长均 24 秒。
- 测试实例没有可直接使用的旧毫秒顶层项目，因此通过现有 blank API 的默认旧格式契约创建独立兼容样例，并在 UI 填写 `00:02:125 → 00:05:875`。保存、刷新后仍显示毫秒，计划 3750 毫秒，输出 3767 毫秒（30fps 帧量化，差 17 毫秒），质检通过。未转换任何已有项目的数据。
