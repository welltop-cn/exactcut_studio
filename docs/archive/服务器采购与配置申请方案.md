## 一、 算力真相与排队模型（为什么需要两套方案？）

在短剧自动剪辑与发布系统中，“**网页在线操作**”与“**视频后台渲染**”对服务器资源的要求截然不同：

1. **网页在线编辑（选剧目、调片段、改文案、打标签）**：
   - 仅消耗极少量的 Web API 与内存资源。无论是 8 核还是 16 核，**即使 50 个人同时在线操作，CPU 占用率也不会超过 5%**。
2. **点击“开始制作”（视频编解码重度计算）**：
   - 系统需要对 1080×1920 30fps HEVC 原片进行解码切片、重编码拼接、AI Hook 字幕排版与合成、技术质检及生成轻量预览。
   - 在 8 核独享 CPU + `veryfast` 参数优化下，**单条 100 秒成片的极限制作耗时约为 2.0 ～ 2.5 分钟**。

### 串行排队延迟模型测算
如果系统处于单任务排队机制下，当 6 名同事在相近时间先后点击“开始制作”时：
- **第 1 个人**：耗时 **2.5 分钟**（在 5 分钟内 ✅）
- **第 2 个人**：耗时 2.5 + 2.5 = **5.0 分钟**（踩线合格 ✅）
- **第 3 个人**：耗时 2.5 × 3 = **7.5 分钟**（超出 5 分钟 ❌）
- **第 6 个人**：耗时 2.5 × 6 = **15.0 分钟**（严重超时 ❌）

> **核心结论**：
> - 如果团队平时是**各自错峰出片**（提交间隔大于 5~10 分钟），**方案 A（8 核）** 性价比最高；
> - 如果团队经常在特定时间点**扎堆集中出片**（如赶排期、批量交作业），要坚守“全员 5 分钟内拿片”的底线，就必须选择**方案 B（16 核）** 并开启双任务并行渲染。

## 三、 两套方案共享的基础设施标准（关键避坑项）

无论采纳方案 A 还是方案 B，以下基础设施策略**必须严格执行**：

### 1. 机房地域：必须选择【阿里云·美西（硅谷）】(`us-west-1`)
- **同机房内网直连 OSS**：正片素材存储在阿里云 OSS 美西，服务器部署在同地域内网（VPC）中，**单集 150MB 素材下载仅需 0.5~1 秒，且完全免费（0 元内网流量费）**。
- **发布直达 Meta**：FBBM (Facebook) 服务器在美国，剪辑完成后直传 Meta API，链路极短、零丢包。
- **国内办公延迟**：国内直连美西延迟约 140~170 ms，对日常 Web 操作完全无感。

### 2. CPU 主频与架构要求：严禁选突发型或老机型
- **主频指标**：基频 **≥ 2.5 GHz**，推荐 **2.7 GHz ～ 3.2 GHz**，全核睿频 **≥ 3.5 GHz**。
- **严禁选型**：禁止选购 `t5`、`t6` 突发性能型（视频满载运行 2 分钟积分耗尽，会被强制锁频在 10%~20% 导致任务挂起）；避免选购 5 代及以前的老旧机型。

### 3. 网络带宽与流量计费：不要选大带宽包月，选按量计费
- **流量大头在内网**：从 OSS 拉素材、上传成品回 OSS 均走阿里云内网，**流量费为 0 元**。
- **公网流量极小**：公网流量仅用于国内 6 名同事在线播放轻量预览视频（单条仅约 4.4 MB）。哪怕每天出片 100 条，一个月公网流量仅约 13 GB。
- **推荐计费方式**：选择 **按使用流量计费 (Pay-By-Traffic)，带宽峰值设定为 30 Mbps**。
  - 开通阿里云免费的 **CDT（云数据传输）每月 20 GB 免费额度**，或购买 50GB 共享流量包（几十元/年），**月度公网流量费几乎等于 0 元或十几元**，且能享受 30M 预览秒开的高速体验。
  - 避免购买 20M 固定包月带宽（每月固定收取 1300+ 元，造成严重浪费）。

### 4. 磁盘规划
- **系统盘**：100 GiB ESSD 云盘（PL0），存放系统与 Docker 运行底座。
- **独立数据盘**：500 GiB ESSD 云盘（PL0 或 PL1），挂载于 `/srv/exactcut`，专门用于正片缓存池、工程切片及成片库。

## 五、 交付后的系统部署与配套改造指引

机器完成交付后，系统上线需配套调整配置：

1. **磁盘挂载与目录权限**：
   ```bash
   mkfs.ext4 /dev/vdb
   mkdir -p /srv/exactcut
   echo "/dev/vdb /srv/exactcut ext4 defaults 0 0" >> /etc/fstab
   mount -a
   ```
2. **OSS 内网 Endpoint 切换**（`/srv/exactcut/config/production.env`）：
   ```env
   # 切换为同机房内网域名，下载零等待且免流量费
   ALIYUN_OSS_ENDPOINT=oss-us-west-1-internal.aliyuncs.com
   ```
3. **根据所选方案调整运行配额（`/srv/exactcut/config/deployment.json`）**：
   - **若采购方案 A (8核)**：
     ```json
     { "cpu_limit": 6.5, "memory_limit": "12g", "public_port": 80, "web_base_path": "/home" }
     ```
   - **若采购方案 B (16核)**：
     ```json
     { "cpu_limit": 14.0, "memory_limit": "26g", "public_port": 80, "web_base_path": "/home" }
     ```
4. **针对方案 B 的软件并发放开**：
   若选定方案 B，开发团队将调整 `source/exactcut/webserver.py` 中的任务队列，将单锁 `running` 改造为支持 `MAX_CONCURRENT_JOBS = 2`（双泳道并行），使 16 核算力充分释放为双任务并发处理。
