# 服务器规格与实测依据

> 历史归档（2026-11-04）。正文保留当时的方案或执行状态，不代表当前版本；日常操作见[文档入口](../README.md)。

> 针对团队 6 人批量出片、采购阿里云美西节点的正式申请单，请直接参阅：[服务器采购与配置申请方案](服务器采购与配置申请方案.md)。

首期按1080×1920、30fps、单任务串行制作估算。独立机器起步建议 **4vCPU、8GB内存、100～200GB SSD**。8vCPU/16GB可用于缩短制作等待和增加余量；500GB仅适合需要长期保存大量素材的场景，不是首期必要条件。

## 生产实例与当前分配（2026-10-09，权威）

美东生产实例（`8.221.122.75`，[部署记录](us-east-deployment-2026-10-09.md)）：宿主 **16 vCPU / 约 30 GiB**，1 TB NVMe。
`config/deployment.json` 实际分配：**`cpus=14.0`、`memory=24g`**（Docker 实测 CPU 额度 14、内存 24 GiB），预留约 2 vCPU / 6 GiB 给系统与 Docker。

- 当前仍是**单任务串行**：16 vCPU 不会自动并行；并发改造见 [并发改造计划](concurrency-refactor-plan.md)。
- 改造后建议容量：`render=3`（每个 ffmpeg `-threads 4`，合计 12 线程，不超订）、`fetch=2`、`upload=2`、`poll` 不占位。
- `pids_limit` 目前由 compose 硬编码 `256`，线程计入，需调高到 **≥512**。
- 东京共享机（1 核 / 2 GiB）只作历史实测基线，不再是生产容量依据。

| 项目 | 首期起步建议 | 扩容条件 |
| --- | --- | --- |
| CPU | 4vCPU，较新的稳定算力型号 | 制作等待时间不能满足需求时考虑8vCPU；需要实测，不能假定线性加速 |
| 内存 | 8GB | 线程数、预览或其他工作负载增加后，按实测峰值考虑16GB |
| 磁盘 | 100～200GB SSD | 按原片、成片保留数量扩容；长期积累大量文件时才考虑500GB以上 |
| 网络 | 对实际素材OSS进行完整GET测速 | 优先稳定吞吐与实际源站距离；下载与编码分别测量 |

## 2026-10-09实测

环境：腾讯云东京共享机，2vCPU、7.3GiB物理内存；Docker运行Python3.11.17/FFmpeg5.1.9，验收容器限制1CPU/2GiB。两集源视频均为HEVC、1080×1920、30fps。制作输出使用libx264、CRF18、medium。未采用GPU硬件编码。

- 第一集157111543字节，完整GET耗时28.721秒，5.217MiB/s；第二集122461144字节，22.603秒，5.167MiB/s。两集合计279572687字节。
- 45秒片段编码耗时约321.1秒，约0.14倍实时速度。CPU持续使用约1核；单段内存约0.8GiB，拼接过程一次采样约0.95GiB，尚不能作为全流程峰值。
- 当前流程先编码片段，再重编码拼接结果，再为Hook重编码整条视频。因此累计耗时不只是一遍编码。
- 同一5秒样本：medium耗时56.953秒、3566249字节、SSIM All=0.994053；veryfast耗时25.863秒、3267947字节、SSIM All=0.993637。约2.2倍速度差，画质指标只代表此样本。这次对比期间另有长片验收运行，不能直接当作独占机器的吞吐预测。
- 拼接期间宿主采样可用内存约5.1GiB，实时swap读写为0，I/O等待为0。当前明确瓶颈是CPU编码，没有证据证明首期需要16GB内存或高端NVMe。

## 容量与资源预算

系统、Docker镜像与构建缓存先按15～20GB预算，两个缓存上限合计16GiB，磁盘预留10GiB，再为临时文件与成片留空间。100GB可作为单实例起点，200GB余量较大；最终按实际保留量调整。缓存回收不会删除正式成片，任何容量都需要归档与保留策略。

换机后要调整`<部署根>/config/deployment.json`：不能只增加主机规格却仍把容器限制在1核/2GiB。4核/8GB独立机器可先给应用3核、5GB；8核/16GB独立机器可先给应用6核、10GB，留资源给系统，并验证多集、Hook、预览与内存峰值。共享机按其他服务实际负载分配。

应用目前使用CPU编码。购买GPU并不会自动加速，需要另行适配硬件编码/解码并验证画质与QC。应先优化编码参数和重复编码流程，再按制作耗时目标评估硬件。

真实两集、多段、标题卡与AI Hook制作已完成：成片101.5秒、1080×1920、30/1fps，QC、轻量预览及缓存复用通过。总耗时包含主动暂停和并行工作，不能用来预测独占服务器的吞吐。正式公网服务与验收范围见[上线记录](server-deployment-2026-10-09.md)。
