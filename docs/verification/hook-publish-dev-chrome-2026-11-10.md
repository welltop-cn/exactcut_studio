Chrome 故障场景使用同一修复版本的真实 webserver.Handler、素材事务、SHA/文件身份检查和前端 app.js。另建私有临时数据副本，复制这 4 条本地产出的成片并核对 SHA；未复制作业、账号库或生产交付回执。原片继续复用本地缓存。

故障条件通过 Chrome 路由延迟/中断/响应注入及隔离状态、缓存/文件替换构造。浏览器始终执行实际产品前端逻辑，真实 HTTP 路由与素材事务负责接收和拒绝。确认性能边界使用真实 start HTTP 请求，并拦截确认期间完整原片的 Path.open；ffprobe 和 JSON/索引读取仍允许，不声称确认无 I/O。

## 审核中修正的测试问题

首轮隔离脚本曾未按 media_file 映射复制绝对成片路径，导致 400；另有两个用例在错误页签查找重新编辑按钮。这些是验收脚本错误，修正后重新跑完整矩阵，未作为产品缺陷或通过证据。

浏览器实测还确认：回执到达时若仍有另一个写请求，前端会保守延迟推进 revision，保留 dirty 内容；该写请求结束并安全刷新后收敛到服务器版本。最终断言验证内容不丢失及后续收敛，没有要求在其他写请求仍在途时强行推进 revision。
