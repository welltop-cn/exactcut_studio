## F7：下载期间切换剧号或项目，原片混入错误目录

复现：点击下载两集 A 剧，暂缓第一集响应，通过页面修改剧号或点击另一项目，再完成第一集响应。

旧代码实际请求第一集为 `fixture / 101494`，第二集变成 `fixture / 101606` 或 `second / 101606`，但保存目录仍是 101494。原生 OPFS 中得到 `['AAA','BBB']`，而应为 `['AAA','AAA']`。两个响应等长，单纯长度检查无法发现这个错误。

根因是 `startOriginalDownloads` 在各集开始时重新读取编辑界面，而 `writeOriginalFile` 也在异步文件操作后才生成请求 URL。目录已固定，但来源还在变化。

修复：点击时一次固定每集的 URL 和预期大小，以及整批剧号；保存函数接收固定 URL。项目切换不取消已开始的下载，也不把后续集转为新项目来源。直接调用保存函数时，其默认 URL 也在第一次异步操作之前求值。

回归使用完整 app.js、实际页面点击/输入、浏览器 fetch 和原生 OPFS；网络出口用确定响应替代，不使用真实素材或生产凭据。检查请求所属项目、剧号和最终文件内容。

## F8：选择目录未结束时，重复点击进入多次下载初始化

复现：第一个单集下载正在等待目录选择，点击另一个单集下载。旧代码的 `running` 只在目录返回后设置，目录选择 API 因此被调用两次。

修复：增加仅用于前端的目录选择状态；下载入口及批量/目录按钮在这期间阻止重复进入。通过 finally 释放状态，取消后仍可重新下载，不把取消当成业务失败。

回归替换浏览器的系统目录选择边界，使等待和取消可确定控制；实际下载按钮及应用状态逻辑保持真实。证明第二次点击不再请求另一个选择器，且取消后可以再次选择。该用例不声称验证操作系统原生选择器外观，也不将两次 API 调用描述为一定弹出两个系统窗口。
