# 段内重编码（只重编码切点和打码所在 GOP）验证记录

2026-11-04 晚（UTC+8），分支 `perf/segment-reencode`，基于 `feat/mosaic-timeline-live-preview` c85898b。复用 perf/smart-cut、perf/mosaic-gop 的 IDR/时间轴校验思路，合并成 `exactcut/segment_reencode.py`，剪切和打码（含“打码 + 删除”一次合成）共用。开关：`cutting.segment_reencode`。

## 规则
- 计划：只在“源闭合 GOP 的 IDR”上切分（IDR NAL、解码序不跨越、帧号 = 解码序号）。每个切点到相邻安全 IDR、每个打码区间向外扩到安全 IDR 的部分重编码，其余按 GOP 原样复制。
- 重编码段：x264 参数与整片编码相同（render.crf / render.preset / yuv420p / 帧率），并带源的色彩标记；段的 profile、level、尺寸、SAR、time_base、SPS/PPS（extradata）必须与源完全一致，第一帧必须是 IDR。
- 复制段：每个包的 sha256、pts 与源逐一相同。
- 校验（一次 `-xerror` 全片解码对照源）：帧数准确；复制帧与源逐像素相同（PSNR=inf）；重编码帧 ≥35 dB；打码段与“同一滤镜图无损作用于源”的参考比较 ≥35 dB。无删除的打码直接复制源音频包并逐包核对；有删除时音频处理与原来完全相同。
- 回退：源不是 avc1 H.264 yuv420p 逐行、帧率不恒定、B 帧延迟 >2、没有安全起始 IDR、一帧试编码得到的 SPS/PPS 与源不同、任一段或最终校验失败 → 整段原样走旧的整片编码。取消和资源让出照常向上抛出。没有新增名额或并发规则。
- `probe_source` 改为读包时间戳（不解码），检查项不变（恒定帧率、零起点、帧数、时长、音画对齐），另拒绝 discard/缺 pts 的包；输出的解码错误仍由全片 `-xerror` 解码覆盖。

## 测试
- 新增 `tests/test_segment_reencode.py`：计划单元测试；6 种删除布局（头、尾、跨 GOP、整 GOP）与整片编码对比 ≥35 dB、复制帧与源一致、音频时长一致；打码 ×（无删除 / 头部删除 / 中段删除）与旧路径对比；非同参数源回退；校验失败回退；读包探测仍拒绝可变帧率。
- `test_mosaic_render::test_mixed_processing_encodes_video_once…`：一帧试编码不计入“视频只编码一次”。

## 画质
- 复制帧：解码 MD5 与源对应帧全部相同（剪切 4057 帧、打码 3822 帧）。旧整片编码这些帧对源 PSNR：剪切最低 46.9 dB；打码最低 26.9、平均 34.9 dB（旧打码路径对每帧都做 gbrp↔yuv420p 转换）。
- 剪切重编码帧（173）：对源 PSNR 新 49.71～/平均 52.11 dB，旧同帧 49.76～/52.48 dB；SSIM 新最低 0.9938，旧 0.9937。
- 打码重编码段：含遮罩的两段对源 PSNR 与旧版逐帧相差 ≥ −0.24 dB（平均相同）；只因删除切点重编码的两段不再经过 gbrp 转换，比旧版高 14～22 dB。
