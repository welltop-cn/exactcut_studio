环境：8.221.122.75，exactcut-production-web-1，us-east-20261019-mosaic-35fe006。

## 同请求证据

北京时间 11:50:36 的 sidebar 请求 d68e82cd97d74637ae6a773ff117527e：浏览器 8551ms，应用 http.completed 8277ms，nginx upstream_header/response 8.277s、连接 0.000s，响应 33661 字节。11:50:59 的请求 2327e520a07144708d25ee7d771f4a65：浏览器 8621ms、应用 8100ms。主要延迟位于服务端处理范围，不能归因于小响应体的公网传输。

初始化 workspace 在 11:50:27 耗时 10.872s，随后 sidebar 8.277s；刷新后 workspace 4.958s，随后 sidebar 8.100s。后续 sidebar 仍有 3.834–7.322s。

## 已确认代码链路

- app.js 初始化等待 workspace，然后 restoreWorkspace 等待 refreshBatches/sidebar，随后才打开选中项目；两次全量汇总串行进入关键路径。
- webserver.py workspace 与 sidebar 都在全局 LOCK 内调用 workflow.summaries(compact=True)。详情读取也使用该锁。
- workflow.summaries 的 compact 只在最终返回时裁剪字段；纳管项目仍调用 material_versions.detail。
- detail 构建资产、编辑权限、历史事件、反馈、下载计划，并调用 validate_draft → validate_hook_layout → _wrap_lines。排版测量与侧栏所需字段无关。
- 前端每 3 秒检查轮询条件，活跃项目按 3 秒、空闲按 15 秒刷新；poll 同时请求 sidebar 和当前详情。重型全量读取因此反复执行。

## 只读函数探针

在生产容器独立 Python 进程中读取现有数据调用 summaries，不启动服务或任务、不改数据、凭据、配置或服务进程。103 个可见项目，其中 81 个纳管项目。

cProfile 冷进程：总计 12.422s；81 次 detail 12.301s，validate_draft 9.680s，99 次未命中缓存的 validate_hook_layout 9.265s，文字宽度测量 261984 次。154 次 can_edit 共 1.311s，read_json 36554 次。剖析器有额外开销，不能把这些秒数直接分摊到历史请求。

另一个无剖析器进程连续两次汇总：首次 8.475s，第二次 1.434s。排版 LRU 首次 hits=48/misses=99，第二次 hits=195/misses=99，证明缓存有效。随后仅在这个临时探针进程替换排版校验为空函数，耗时 1.443s，侧栏输出与上次相同；退出前恢复函数。此实验不改变 Web 进程，不是修复或性能验收。

## 结论与边界

侧栏复用完整详情且全局持锁，初始化重复汇总，是已证实的性能设计问题。冷缓存排版是实测热点；热缓存仍有超过一秒的全量读取。不可声称每次线上 8 秒都在排版：历史请求未记录锁等待/锁内计算分段，缓存状态及并发 CPU 争用也未逐请求采集。同期详情出现约 7.474s 而 queue 仅约 0.064s，与共享锁阻塞相符，但尚未量化锁等待。

建议修复：为 sidebar 提供只读取权威状态并计算相同状态规则的轻量投影；避免构建完整详情和排版/编辑能力校验；workspace 恢复有效已选项目时避免全量详情汇总。须回归权限、归档、删除、候选版本、待交付与失败状态的一致性，并补充锁等待与汇总分段耗时。当前未部署任何修复。

## 发布后发现的第二处瓶颈

6a5de9a 发布后独立进程汇总已降至 0.146s（含剖析器开销），但浏览器首次 sidebar 仍有 5.761s，后续 0.727–1.376s。继续追踪全局锁调用方，发现 worker_tick 持锁执行 recover_jobs；末尾孤儿检查对每个非纳管执行目录调用 runtime，后者 production_summary 每次重新读取所有任务。

真实生产只读对照：299 个执行目录、778 份任务，原路径剖析耗时 7.939s，read_json 232854 次；同一轮共享任务快照耗时 0.090s，299 份 runtime 输出完全一致。修复复用恢复阶段结束后已有的最新 stored_jobs 快照，保留阶段完成新建后继任务的可见性和现有锁边界。新增测试在旧实现失败，在修复后通过；调度、恢复和侧栏相关 109 项通过。
