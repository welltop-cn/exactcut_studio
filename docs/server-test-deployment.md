# 服务器独立测试实例

本文维护测试部署的流程与边界，不维护一个固定服务器的实时状态。旧实例的地址、容器、凭据位置、各次 release 与启停记录见[历史交接](archive/server-test-deployment-before-cleanup-2026-11-04.md)；其中较晚记录已覆盖较早的“当前”描述。

## 隔离要求

- 先测试验收，再单独授权生产发布；测试成功不代表允许修改正式服务。
- 代码、配置、账号、数据、原片和端口独立。不挂载生产 data，不复制活动任务、数据库或交付回执，不硬链接可写生产媒体。
- 实例使用 production 环境标记不代表它是正式服务，也不代表交付或外部写入已经授权。
- 本轮并发验收只允许 OSS `exactcut-previews/test/`，配置 `preview.namespace=test`；FBBM/飞书/CF-Ads 写入禁用或拦截。历史某轮的临时写入例外不自动沿用。
- CPU SAM、模型文件及依赖按已验收测试配置固定；Mac 结果不能替代 Linux CPU 和长片验收。

## 更新流程

1. 在已审核、已提交的固定版本上完成相关验证，记录提交、包/镜像摘要及依赖变化。
2. 只读核对测试实例和正式服务的版本、启动时间、挂载及资源；确认没有其他会话或用户任务。
3. 准备独立候选目录或固定镜像，不更新运行中 Python 源码，不覆盖数据。
4. 沿用该实例已核对的管理脚本正常停止、切换和启动。依赖变化时重建测试镜像，不能只更换应用文件。
5. 核对候选源码/镜像身份、挂载、有效 runtime 和功能开关。静态 release 字符串不等于真实提交证据。
6. 在用户实际网络上完成登录、项目加载、目标操作和需要的播放检查，记录业务结果及未覆盖项。
7. 对比正式服务的版本和启动时间，确认未受改动；更新验收记录。

已有测试容器如果绑定源码目录，重命名宿主目录不会自动更换旧绑定，须按对应管理脚本重新创建测试容器。不要向命令传入正式容器名。

## 配置与验收

网页前缀通过集中 JSON 配置的 `web.base_path` 设置，例如 `/test`。当前实现不读取 `EXACTCUT_WEB_BASE_PATH`。使用 `EXACTCUT_CONFIG_FILE` 指定独立覆盖文件，保留该实例已有其他配置。

实际执行能力由环境、worker、AI、下载、交付及预览开关共同决定；只关闭普通 worker 不能证明全部交互处理已经关闭。核对[当前架构](architecture.md)与实际启动脚本，不直接复用历史 recreate 脚本恢复后台能力。

健康检查只说明服务响应。完整验收根据变更至少区分：页面/API、真实媒体、真实模型或替身、队列/恢复、输出校验、播放、远端回执。队列完成不能代替当前素材版本与业务成功。

使用 Linux 验证镜像运行完整测试时，需提供干净的完整仓库和所需测试工具。仅供部署的应用白名单包缺少 tests、README 或 integrations 上下文，不能用于宣称完整回归。

## 回滚与记录

失败时只回滚经确认兼容的测试代码/镜像，保留测试账号、项目、日志和失败媒体。不要还原旧数据库、删除数据目录或靠重启正式服务修复测试环境。

记录源提交、摘要、有效配置、测试数据来源、真实/模拟边界、输出和播放结果、回滚方式、正式服务前后对照。生产操作另按[部署说明](linux-migration.md)及[线上变更索引](production-change-log.md)执行。
