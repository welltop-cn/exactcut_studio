# sources 预取任务去重

根因：帧格式素材尚未就绪时，`source_prefetch.status()` 已根据活跃任务将状态设为 `queued`，后续帧格式分支却只接受 `waiting`，将其覆盖回 `waiting`。反复请求 sources 因而被当成缺少素材并重复建任务。

修法：帧格式分支接受已有的 `queued` 状态，保留活跃任务的排队状态。`prefetch_sources()` 在建任务前，再按本批次、本实例、同剧且状态为 `queued` / `running` 的预取任务过滤已覆盖集数，只为新增集数建任务。`LOCK` 与 `PREFETCH_LOCK` 按固定顺序包住任务列表读取、判断、保存和入队。纳管入口不预持全局锁，旧入口预持全局锁；全局锁现为可重入 `RLock`，统一先取 `LOCK` 再取 `PREFETCH_LOCK`，防止读取已有任务时的反向等待。该组合回归由 `de8d7e7` 修复，测试覆盖已有任务下两类入口并发完成且不重复建任务。

边界：`completed`、`failed`、`interrupted`、`cancelled` 不算活跃覆盖；失败任务仍需显式 `retry=True` 才重试，重试也不会重复创建已有活跃任务覆盖的集数。不同批次、实例、剧目的任务互不阻挡。素材就绪、下载中、建索引及失败的判断保持原有行为，不改动剪切、打码、制作任务或前端。
