## 进程控制与环境隔离修正

应用不再直接读取 `/proc`。Mac 和 Linux 使用 `ps -ww` 查询明确的 PID、PGID、状态和命令列；Docker 安装 `procps`。每次启动以 CPython `-X exactcut_process_token=<随机32位hex>` 标记，不改变业务模块的参数。发信号前验证当前实例、独立进程组及唯一标识；PID 复用、其他实例、僵尸或无法核验的进程不被当成可控制对象。查询工具失败抛错，阻止调度继续猜测。

独立审查复现并修正三类重启边界：父进程在启动后但保存 PID 前退出，按预存的启动标识找到并接管原进程；同批次多个发布任务只匹配自己的标识，其他任务保持排队；运行身份已保存但控制记录尚未写入时，恢复控制记录。已失效的本实例子进程记录清理，避免历史 PID 查询随任务积累。真实 Mac 子进程暂停/恢复、删除与无 PID 的启动恢复均有回归。

开发启动器显式指定 `config/default.json`，不再继承终端中的生产 `EXACTCUT_CONFIG_FILE`。回归用独立临时目录验证；未读取生产凭据。

旧的 starttime 记录保留在原业务数据中，作为历史字段读取；没有新标识时不据此发送信号。后续上线须先通过已有发布管理器等待活动任务结束，不在运行期间切换身份协议。
