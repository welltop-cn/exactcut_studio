# 剪切打码后台队列设计与开发验收约定

状态：用户已确认业务行为，交 D1 实现，本会话负责完成后 review。
基线：main / 5b0e4081b7c894f1f5b03213e100dd5de5347852。

## 目标与范围

用户提交最终剪切打码请求后，服务端持久执行；关闭编辑器、切换项目、刷新、关闭浏览器不影响任务。其他素材可打开、编辑、提交。重新进入同一素材编辑器恢复任务状态、当前阶段与可获得的进度，完成后预览并确认替换。素材列表不增加进度；不承诺剩余时间。

覆盖统一剪切打码入口中的仅剪切、仅打码、混合请求；核实仍可访问的旧剪切入口，不能绕过同素材保护。片段预览和自动识别不作为最终提交任务，必须避免其资源使用阻塞其他素材基础编辑。

## 已确认业务规则

1. 提交成功即冻结视频版本及全部剪切打码参数。以服务端持久化成功为提交成功，不依赖浏览器轮询驱动任务。
2. 同一素材 queued/running/cancelling 期间不可修改、编辑或重复提交；播放、查看状态、退出允许。服务端对所有用户和窗口强制执行。
3. 完成后进入待确认：可预览，必须确认替换或放弃结果后才再次编辑。确认后基于新成片；放弃后保留原成片与上次参数供调整。
4. 排队任务可取消；运行任务可请求停止，停止实际完成前保持锁定并显示正在取消。取消和失败保留原成片、提交参数并解锁，用户可修改重提。
5. 不自动替换，不自动发布，不新增素材列表进度。
6. 用户偏好每用户串行队列；服务器资源不足可全站串行。实现按用户 FIFO、跨用户公平调度并设置全站并发上限，默认 1。在有服务器负载与代表性任务峰值证据前不提高。不同用户最多各运行一个任务；资源忙保持排队而非拒绝其他素材提交。按用户轮转，不让单用户积压饿死其他用户。

## 当前代码证据与实现边界

- `source/exactcut/mosaic_render.py:start` 在请求中获取 compute.lock，并把租约交后台线程；当前没有最终处理的持久队列。其 recover 把失去 worker 锁的 running 标记失败。
- `mosaic_session.py:open_session` 首次创建视频快照也获取 compute.lock，导致已有长任务阻止下一素材打开。
- `mosaic_scan.py`、`mosaic_tracking.py`、`cutting.py` 等也使用 compute.lock。不能只移除锁而导致无限并发；区分短时准备/交互与重任务，审计全部相关路径与锁顺序。
- `cutting_access.py` 已有项目/素材跨进程 gate、交付保护、版本校验。扩展现有入口规则，不另建一套能绕过的编辑规则；读状态与预览不可因新锁被挡住，worker 自身及确认替换必须通过明确内部路径避免自锁。
- `mosaic_replace.py` 已支持结果确认替换与替换中断恢复，复用现有媒体提交协议。
- `preview_subtitle_queue.py` 提供持久 JSON、原子写、跨进程 dispatcher lease 和启动恢复参考；字幕队列与本功能独立，禁止共用其 queue.json 或改变字幕业务语义。
- 前端 `source/exactcut/web/mosaic.js` 与相关 HTTP adapter 按现有约定扩展。API 字段、身份来源和配置项先检查真实代码；本文定义业务状态，不声称现有 API 已存在这些字段。

## 状态与持久化

业务状态：编辑 → 排队 → 执行 → 完成待确认 → 确认替换/放弃；排队可直接取消，执行可进入取消中；失败/取消可回编辑重提。替换失败保留可重试结果，不误报已替换。

复用 schema_version=1，使用兼容扩展。任务持久保存稳定任务身份、认证用户身份、项目与素材身份、源版本/哈希、提交参数快照、提交顺序、执行/取消/结果状态、阶段与进度。字段和存放位置由 D1 在确认现有契约后确定并记录。客户端不能伪造归属用户。

队列与任务状态要有明确权威及写入顺序：任何持久化步骤崩溃后可恢复，不能出现提交成功却永远不执行、同素材重复占位或完成后再次调度。固定锁顺序并记录，队列锁内不执行视频处理/网络调用，也不长期等待 compute.lock。跨进程只有一个调度所有者，保证不能超出并发上限。

刷新/GET 状态不提交新任务；重复点击和请求重试幂等。取消后再次提交相同参数应产生可执行的新尝试，不能被旧取消任务吞掉。执行前、确认替换前复核源版本与权限，过时任务不可覆盖新成片。

重启：排队任务继续；无存活 worker 的执行任务，在确认旧进程不再执行后可从头恢复，保留可验证缓存，设置有限恢复次数，失败可手动重试，不能无限崩溃循环。取消意图持久化，重启不得复活已取消任务。不自动重发付费识别请求。维护/关闭期间停止领取新任务；将本队列纳入已有维护和排空检查，避免漏算活动任务。

原片删除、版本替换、重新制作、项目级修改/删除等冲突写入同样需要保护；访问控制保持原有项目权限。旧任务和旧 session 兼容读取，不因升级把历史完成结果重复执行。

## 编辑器行为

打开后先恢复服务端最新任务及参数，再决定交互状态；不能短暂启用修改或自动扫描后才发现任务锁定。排队显示等待处理，若展示位置须符合用户轮转语义，不展示虚假的全站 FIFO 名次。执行显示实际阶段、现有可获得进度。取消显示取消中，直到服务端确认终止。完成展示结果预览、确认替换、放弃结果。退出编辑器不发送停止/放弃最终任务。轮询失败应提示连接暂时异常并恢复查询，不能解锁或判失败。快速切换素材时旧异步响应不能更新新素材 UI。

## 验收矩阵

| 范围 | 必测场景及断言 |
|---|---|
| 基本处理 | 仅剪切、固定打码、跟踪打码、混合；真实输出时长/帧数/音频与打码区间正确；未确认原片哈希不变 |
| 连续提交 | A 执行时打开 B、编辑、提交 B/C，前台不被计算锁阻塞；后台达到配置上限但不超额，同用户串行 |
| 公平性 | 两用户各提交多个任务，用户内部 FIFO，跨用户不饥饿；同用户跨项目仍同一队列 |
| 生命周期 | queued/running/cancelling/完成待确认各阶段退出重入、刷新、关闭后重新登录，状态与参数恢复；无自动重提/取消 |
| 冻结保护 | 多窗口/不同用户/直接 API 尝试改参数、重新生成、旧剪切入口、替换/删除素材及项目冲突写入均按规则阻止；其他素材不受影响 |
| 幂等竞态 | 双击、请求超时重发、同时提交同素材只产生一个任务；取消后相同参数可重提；取消与领取/完成竞态无重复执行/错误解锁 |
| 取消 | 取消 queued 不启动；取消 running 真正结束子进程后解锁释放槽位；取消保留原片和参数，下一任务继续 |
| 确认 | 完成待确认不占计算槽位；未确认不能新编辑；确认生成新当前版本；放弃保留旧片和参数；重复确认幂等；替换失败可重试 |
| 故障恢复 | 入队与报告写入间、领取后、执行中、完成写入与槽位释放间重启；无丢单/重复产出/永久锁；取消意图保留；有限恢复失败不堵后续任务 |
| 权限版本 | 未授权状态/取消/确认不可访问；身份不可伪造；源版本变化、输入缺失、磁盘不足、处理失败明确结束且不覆盖新片 |
| 资源交互 | 重任务期间打开另一素材、抽帧、手动配置可用；自动识别/片段预览有受控资源策略；字幕及原制作队列回归 |
| 前端异常 | 轮询断网重连、快速切换素材、旧响应晚到、重复开关；无串素材、误解锁或 JS 异常 |
| 兼容维护 | 旧会话和历史结果读取；多进程 dispatcher 排他；维护排空看到本队列；关闭后没有失管 FFmpeg |

每项记录实际用例与结果，不用纯 mock 代替真实媒体和浏览器验收。跟踪模型若本地不可用，明确哪些为模拟、哪些为真实验证，不声称覆盖真实 SAM。完整回归的 skipped 与失败必须说明。
