## 日常开发

1. 在开发库为一个任务创建分支，例如 `bugfix/BUG-01-timecode`。
2. 先保留复现样本和错误结果，用副本或脱敏数据复现，不读取生产密钥。
3. 修复后运行相关测试，最后运行 `.venv/bin/python -m pytest -n auto`（默认只跑 unit 层）和 `git diff --check`；合入 `main` 或发版前再跑 UI 层和集成层，见下文「测试分层」。
4. 提交代码，提交说明引用任务编号，并记录真实样本验收结果。
5. 更新验收清单，通过后合入 `main`。本次基础设施版本保留在 `infrastructure/safe-release` 历史及版本标签中。

### 测试分层

测试按实测行为分三层，标记注册在 `pyproject.toml`，规则在 `tests/conftest.py`：

| 层 | 标记 | 内容 | 命令（在 `source/` 下） |
|---|---|---|---|
| unit | 默认（`unit`） | 不开浏览器、不调 ffmpeg/ffprobe、不处理真实媒体；每次改完都跑 | `python -m pytest -p no:cacheprovider -rfEs -n auto` |
| ui | `ui` | 启动 Playwright 浏览器 | `python -m pytest -p no:cacheprovider -rfEs -m "ui and not integration" -n 4 --dist loadfile` |
| integration | `integration` | 调 ffmpeg/ffprobe 或处理真实媒体（含浏览器加真实媒体）；合入 `main` 或发版前跑 | `python -m pytest -p no:cacheprovider -rfEs -m integration -n auto --dist loadfile` |
| 全量 | | 三层合计 | `python -m pytest -p no:cacheprovider -rfEs -m "" -n auto` |

- 新增测试如果启动浏览器、ffmpeg 或 ffprobe，要加 `@pytest.mark.ui` 或 `@pytest.mark.integration`（整文件可用 `pytestmark`）。漏标的 unit 测试会被 conftest 守卫直接判失败。使用 `editor/page/frame_page/player/playback` 等浏览器 fixture 的测试会自动补 `ui` 标记。
- `flaky_fs` 标记依赖文件系统时间戳粒度、已知不稳定的用例。
- 每个测试进程（包括每个 xdist worker）有独立的 `EXACTCUT_DATA_ROOT` 临时目录。UI 测试通过 `tests/browser_support.py` 在进程内共用一个 Chromium，每个用例使用新的 context。
- 不装 pytest-xdist 时去掉 `-n` 参数即可串行运行。

`bin/setup` 安装 `requirements.lock.txt` 锁定的版本。更改依赖时更新锁定清单并重新测试；不得升级线上虚拟环境。发布构建使用当前开发库中已验证的独立运行依赖，和锁定清单逐项核对，并存档依赖文件校验值。

## 发布

运维入口：`/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops`。

```bash
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops status
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops build v0.1.2 --ref main
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops publish v0.1.2
```

构建拒绝未提交的源码；发布版本名称不得重复。构建保存 Git commit、完整测试结果、Python/FFmpeg 版本、源码与依赖的 SHA-256 清单，并检查实际依赖与锁定清单匹配。发布先验证档案，再在独立验收数据目录启动候选服务。

正式切换时关闭新的写入请求并等待已有请求完成；已有后台任务继续执行。默认最多等待 300 秒，超时会取消发布，不能强杀制作任务。任务结束后停止网页服务，保存当前工程备份，修改 LaunchAgent 指向候选版本，恢复服务并检查版本健康。工程备份不复制原片、成片和业务目录。生产任务只有一个执行器，开发执行器不能控制其他环境的进程。

首次建立基线时已短暂停止服务。后续发布仍可能有短暂连接中断，不能保证零停机。静默阶段保留查看与预览，写入请求提示维护。

发布完成后的人工验收包括：登录、查看已有批次、预览与拖动、模板下载、提交测试制作、失败重试、确认上传和继续同步。真实上传应使用明确批准的测试素材；自动检查不创建生产远端素材。版本健康或关键功能异常时立即回滚。

## 回滚

```bash
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops rollback
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops rollback --to baseline-20261006
```

默认退回上一次生产版本，也可指定已存档版本。回滚同样验证校验值、数据兼容性、空闲任务状态和健康检查，并在切换前保存当前工程备份。新版本启动失败会自动恢复原 LaunchAgent；恢复失败保留错误，需立即检查服务日志。

正常回滚只切换代码、依赖和部署配置，保留最新账号、批次、成片、反馈及上传记录。当前数据兼容版本固定为 1，工具拒绝自动升级或切回不兼容版本。历史远端 OSS、飞书及 Facebook 数据不会被撤销。

Git 的 baseline 标签表示当前磁盘源码基线；运行版本是否一致还需要版本健康信息和实际部署路径确认。旧基线没有新 `/healthz` 版本字段，回滚时结合 LaunchAgent 路径核验。

```bash

/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops verify /绝对路径/某个备份
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/ops bundle
```

2026-10-07 按用户明确要求，将后续手动、每日、发布前及回滚前备份统一改为工程范围。原片、制作素材、用户 Excel、账号数据库、任务状态和反馈均不纳入新备份，不扫描 `projects`、`feedback` 或整个 `.web-state`。历史业务备份保留，不自动删除。

新备份保存当前已发布版本的校验通过源码、依赖锁定清单、版本/提交/测试/运行环境记录、完整 Git 分支与标签历史 bundle、运维控制脚本及入口、部署 settings 和本应用 LaunchAgent。生产 `.env` 与 `.web-state/cloudflared.yml` 是明确列出的工程配置例外；只复制这两个配置文件，不复制其所在业务目录。配置可能含密钥，备份目录为私有权限，密钥不进入 Git。

每日备份由 `com.oulagrowth.exactcut.backup` 在北京时间 04:00 执行，输出与错误日志分别保存在 ops/logs/backup.out.log 和 backup.err.log。手动和每日工程备份通过运维锁与版本切换互斥，但不进入维护、不等待制作空闲、不停止网页或执行器。发布/回滚仍需等待任务完成，只在切换代码时短暂停止网页。

每个工程备份包含文件 SHA-256 清单，并校验 Git bundle；失败的半成品备份清理掉。复制使用独立 inode，禁止以硬链接代替。当前及历史发布目录继续保留完整只读源码和运行依赖，正常回滚直接切换这些版本，保留当前业务数据。工程备份的 `code` 不重复打包 `.venv`；跨机器恢复需依据锁定依赖和环境记录重建，再隔离验收。

恢复工程档案前先用 `verify` 校验，在隔离目录恢复源码或克隆 `history.bundle`，完成构建及验收，再通过发布工具切换。新工程备份不提供业务数据的时间点恢复；普通代码回滚不恢复旧数据库、不覆盖原片/成片，不撤销远端上传。需要单独恢复业务数据时必须另行明确范围。

用户已决定暂不增加第二块磁盘。当前使用本机工程存档和冻结发布版本，暂不开展异地备份，也不新增付费云资源。备份不自动删除，低磁盘空间时拒绝继续，需人工审查留存和归档。

运行依赖已单独保存，但 Python 解释器和 FFmpeg 仍依赖本机安装。升级 Homebrew/Python/FFmpeg 或迁移主机属于独立变更，须重新验收所有保留回滚版本；不能假定跨系统仍可直接回滚。

## 隧道连接配置

2026年10月6日验收发现公网原有 1033 故障。系统 DNS 将 argotunnel.com 解析为 198.18.* 地址，Cloudflare 公共 DNS 则返回真实边缘地址。此错误已存在于迁移前基线日志中。

已仅修改本应用的 Tunnel LaunchAgent，保持原 Tunnel ID、域名和本机端口，使用 HTTP/2 连接两个经公共 DNS 验证的真实边缘地址。TLS 验证保持启用，系统 DNS、VPN 和其他 Tunnel 均未修改。原配置与候选配置保存在 ops/tunnel-history，生效记录保存在 tunnel-current.json。

固定边缘地址通过当前 cloudflared 版本的 edge override 参数实现，该参数在官方源码中标为内部测试用途，因此这是针对当前网络环境的连接恢复方案。更新 cloudflared、切换网络或边缘地址失效时必须重新验收；长期应修复 VPN 的 DNS 配置并恢复正常自动发现。

```bash
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/tunnel status
/Users/admin/Desktop/codex/exact-cut-fbbm-ops/bin/tunnel rollback
```

隧道回滚只恢复之前存档的 Tunnel LaunchAgent。原 DNS 问题未修复时回滚会重新出现公网故障，因此不要把它当作普通应用代码回滚。应用的 `ops rollback` 保持当前正常工作的隧道配置。
